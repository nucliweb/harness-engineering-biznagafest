# Demo flow

Five tickets in `tickets/`, each with a role in the talk. The app is a fictional conference agenda; it only has to be predictable and layered.

| Ticket | Title | Role | State in the repo |
|---|---|---|---|
| FEATURE-1 | Filter talks by track | The worked example: every artefact the four phases produce | Complete run; `specs/FEATURE-1/` committed with `00` to `04` and `journal.jsonl` |
| FEATURE-2 | Favourite talks persisted in localStorage | The ticket too big for one PR: Gate B returned `Split` and the run stopped for a person | Stopped at phase 2; `specs/FEATURE-2/` committed with `00` to `03`, `BLOCKED.md` and the journal |
| FEATURE-3 | "Now" indicator on the schedule | The second complete run, headless; shows the Gate B calibration in its journal | Complete run; artefacts and journal committed |
| FEATURE-4 | Filter talks by room | The recorded one, and the clean ticket for anyone who clones the repo | Run for `docs/recordings/headless-feature-4.cast`, then reset: `specs/FEATURE-4/` keeps only `journal.jsonl`, no artefacts and no code |
| FIX-1 | Browser tab title never changes | A real defect, kept unrun: the fix to try, so the flow is seen on something other than a feature | No `specs/FIX-1/` |

`/spec-retro FEATURE-1 FEATURE-2` wrote `specs/retro.md` and `lessons.json`. Lessons come only from friction entries, so a ticket that stops at Gate B adds context to the retro but no lessons. A lesson becomes `confirmed` when the same friction shows up in a second ticket; `/spec-plan` loads confirmed lessons for the layers a ticket touches. That is the loop the journal closes.

## In the talk

Nothing runs live. The speakers walk `docs/demo/index.html`, a page generated by `scripts/build-demo-page.mjs` from the FEATURE-4 recording, the artefacts, the journal and the metrics: nine screens, one real run, the lines that matter framed with a narration card each. Then the repo, file by file: `specs/FEATURE-1/03-plan.md` and `specs/FEATURE-1/journal.jsonl`. Exact order and timings: `docs/demo-script.md`.

## Resetting FEATURE-4 after a run

Delete the artefacts (keep `specs/FEATURE-4/journal.jsonl`) and revert the code it produced on a committed tree: `git checkout -- apps packages` for the modified files and `git clean -fd -- apps packages` for the new ones. The runner refuses to start while either kind remains.
