# From the slides to the repo

Each row maps a part of the talk to the files that show it. Open the files in the order listed. Paths are relative to the repository root.

| Part of the talk | Files to open, in order | What to point at |
|---|---|---|
| What a harness is: Claude Code plus skills, hooks, subagents and scripts | `.claude/settings.json`, `.claude/skills/`, `.claude/agents/`, `.claude/hooks/`, `.claude/scripts/README.md` | Four kinds of file in one folder. Claude Code is the engine; everything else is plain text and scripts you can copy. |
| Context beyond the code: team conventions and per-layer `CLAUDE.md` | `CLAUDE.md`, `packages/core/CLAUDE.md`, `packages/ui/CLAUDE.md`, `apps/agenda/CLAUDE.md`, `.claude/skills/monorepo-conventions/SKILL.md` | The root file states the layers; each package states its own rules; the skill loads them for every phase. |
| SDD overview: four commands, each pausing | `.claude/skills/spec-help/SKILL.md`, `docs/contracts.md` section 9 | The table of phases and the "Pauses at the end" column: a person launches the next phase. |
| Phase 1, clarify | `.claude/skills/spec-clarify/SKILL.md`, `.claude/agents/explorer.md`, `specs/DEMO-1/00-clarification.md`, `.claude/scripts/validate-clarification.mjs` | Questions cite real code, "Open questions" must be `- None`, and a script, not a model, decides the artefact is valid. |
| Phase 2, plan with gates A, B and C | `.claude/skills/spec-plan/SKILL.md`, `.claude/skills/spec-help/references/gates.md`, `specs/DEMO-1/01-research.md`, `specs/DEMO-1/02-design.md`, `specs/DEMO-1/03-plan.md`, `.claude/agents/plan-auditor.md`, `.claude/skills/spec-help/references/auditor-families.md` | Gate A in `02-design.md` (alternatives, closed decisions), Gate B thresholds in the skill, Gate C as the `## Audit` line at the bottom of `03-plan.md`. |
| Phase 3, implement: developer and reviewer per package, in series | `.claude/skills/spec-implement/SKILL.md`, `.claude/agents/developer-package.md`, `.claude/agents/reviewer-package.md`, `specs/DEMO-1/03-plan.md` | The order `core -> ui -> agenda`, a different model reviewing each layer, and the ticked `[x]` steps that make the plan resumable. |
| Phase 4, validate: global checks and the design QA loop | `.claude/skills/spec-validate/SKILL.md`, `.claude/agents/validator-global.md`, `specs/DEMO-1/04-dod.md`, `.claude/agents/design-qa.md` | `04-dod.md` is a table of exit codes with a verdict. `design-qa` is optional and needs a browser, so headless runs skip it. |
| The journal as friction memory, and the retro | `docs/contracts.md` section 5, `specs/DEMO-1/journal.jsonl`, `.claude/scripts/journal-append.mjs`, `.claude/hooks/journal-capture.mjs`, `.claude/skills/spec-retro/SKILL.md`, `.claude/scripts/lessons-aggregate.mjs`, `specs/lessons.json`, `specs/retro.md` | Only failures, deviations and human decisions are recorded. `lessons-aggregate.mjs` promotes a lesson at two tickets, and `spec-plan` loads it. The last two files exist once `/spec-retro` has run. |
| The headless autopilot | `scripts/headless.sh`, `.claude/skills/spec-help/references/headless.md`, `docs/run-metrics.md`, `specs/DEMO-1/journal.jsonl` | The conservative defaults table, one row of time and cost per phase, and the `blocked` entries from the first validate attempt. |
| PR triage and adversarial review between two models | `scripts/adversarial-review.sh`, `scripts/prompts/reviewer.md`, `scripts/prompts/rebuttal.md`, `scripts/prompts/reviewer-reply.md`, `scripts/lib/parse-review.mjs` | An Opus reviewer, a Sonnet rebuttal, at most 3 rounds, then `CONSENSUS` or `NO CONSENSUS` and a person decides. The PR triage itself is not reproduced; the script is the reviewing core. |
| Progressive release behind flags | None | Not reproduced. The repo has no feature flags, CI or deploy pipeline. It stops at a validated diff. |
| Lesson 1: predictable code makes a reliable agent | `eslint.config.js`, `packages/core/CLAUDE.md`, `packages/ui/CLAUDE.md`, `apps/agenda/CLAUDE.md`, `docs/contracts.md` section 2 | The `no-restricted-imports` rules that fail the build when a layer imports upwards. |
| Lesson 2: every piece in its place | `.claude/agents/`, `.claude/skills/spec-help/references/agents-and-models.md`, `README.md` ("Agents and models") | One job, one model, one tool list per agent, with the price per million tokens next to it. |
| Lesson 3: validate with scripts, not with models | `.claude/scripts/validate-plan.mjs`, `.claude/scripts/fixtures/plan/`, `.claude/scripts/validators.test.mjs`, `specs/DEMO-1/04-dod.md` | One valid fixture and several invalid ones, each failing for a single rule. No model call inside any validator. |
| Agents and skills with clean context | `.claude/agents/explorer.md`, `.claude/agents/developer-package.md`, `.claude/skills/spec-plan/SKILL.md`, `docs/claude-code-reference.md` | Each agent receives a brief with the ticket, the question and the return format, and nothing else from the conversation. |
| Hooks as the deterministic part | `.claude/settings.json`, `.claude/hooks/post-edit-eslint.sh`, `.claude/hooks/post-edit-eslint.test.mjs`, `.claude/hooks/journal-capture.mjs` | Two hooks, no model call, both tested. The lint hook answers on the same tool call that made the edit. |
